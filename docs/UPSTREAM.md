# Porting upstream into ChatBBC

ChatBBC 2.2.0 is a downstream of [Chat On Steroids](https://github.com/totec448-spec/chat-on-steroids), pinned to commit `dee4b5e94b8598d7630e6db62bada9ac6050f457` (upstream version 2.1.18). The [downstream change map](upstream-map.json) is the machine-readable authority for changed paths, exact upstream anchors, port rules, checks and retained brand-string exceptions. This runbook explains the procedure; it does not replace that map. Preserve the upstream MIT license, contributors and third-party attribution when porting.

## Product boundary

- Display name: **ChatBBC**; package, executable and bridge slug: `chatbbc`; app ID: `com.chatbbc.app`; desktop file: `com.chatbbc.app.desktop`. Companion display name: **ChatBBC Companion**.
- Connector titles: **ChatBBC Core**, **ChatBBC Desktop**, **ChatBBC Plugins**; server IDs: `chatbbc-core`, `chatbbc-desktop`, `chatbbc-plugins`. App and companion use bridge protocol **18**. A foreign slug and a mismatched same-slug protocol fail independently; do not equate them.
- Supported release target: **Linux x64 AppImage**, plus the unpacked directory for local smoke. Native desktop screen/input is not added on Linux; Desktop connector browser tools remain available. Keep shared cross-platform source/helpers where functional code depends on them, without promising Windows, macOS or ARM release support.
- Saved manual Appearance settings live in config. The main-process Omarchy theme reader reads only `~/.local/state/omarchy/current/theme/colors.toml`, publishes an in-memory state snapshot, and projects its palette when **Follow Omarchy theme** is enabled and a valid palette exists. An unavailable palette falls back to saved manual values; live colors never overwrite config. No theme shell execution, installed hook, poller or browser theme-sync protocol.
- Preserve internal `COS_CONTEXT`, `CLF-HANDOFF`/`CLF-RESUME`, `clf` URL markers, `cos-*` page messages/DOM attributes, `CLF_*` and `COS_*` environment keys, `.cos-github.json`, and persisted renderer preference keys such as `chat-on-steroids.sidebar-order`. These are protocol or stored-data identifiers, not public branding. The map lists exact retained occurrences and reasons; do not run a global brand replacement.

## Local gates and publication

Repository Actions are disabled; do not restore `.github/workflows` or use hosted runners, Actions artifacts, workflow dispatch, or `act` as acceptance evidence. Build and verify on Linux x64 with the project-compatible Node/Electron runtime and the exact lockfile. Run `npm ci`, `npm run verify:rebrand`, `npm run verify:upstream-map`, `npm run verify`, `npm run build`, `npm run verify:ui`, and `npm run dist:linux:x64`; inspect the real Wayland UI, packaged runtime, companion and MCP paths. `npm run release:local` builds a checked local candidate with manifest and SHA-256 checksums; source tests do not prove a GUI/package/provider flow. A later explicit `npm run release:publish -- --tag v2.2.0` requires a reviewed immutable tag, an absent release, disabled Actions, online tunnel freshness and an asset readback before a draft is published. Do not create a tag, push or publish as a side effect of a port.

## Future port procedure

1. Fetch upstream **without tags**. Record old and new exact SHAs and inspect `git diff --name-status <old> <new>`. Require the baseline Git object locally; if absent, fetch it explicitly rather than inventing a base.
2. Branch from ChatBBC main. Apply upstream patches file by file with a three-way merge against the recorded upstream base. Do not merge unrelated Git histories, restore hosted workflows, or globally replace brand strings.
3. For every changed mapped path, consult its `portRule`: reapply identity values and single-source artwork, merge functional fixes into shared owners, keep the main-owned live Omarchy palette outside persisted config, translate hosted checks to local scripts, and preserve license bodies and authored user prompt customizations. Record the original upstream PR/author and contributor credit for incorporated work.
4. For a partial/cherry-picked update, retain the full-import upstream SHA; add exact adopted upstream commit/path records in optional `ports`. Advance the baseline SHA only after accounting for the **entire** upstream delta.
5. Review incoming unmapped paths for branding, packaging targets, prompt contracts, protocol changes and workflows. Update the map and precise `retainedIdentifiers` exceptions; enumerate each changed/added/deleted path exactly once. Keep historical reports historical, not current-product instructions.
6. Run `npm run verify:upstream-map`, `npm run verify:rebrand`, relevant regressions, full local verification, GUI/companion smoke and a local candidate build. Record actual evidence at the appropriate source/test/build/package/live level and upstream authors/PR links, never confidential sessions or credentials. Do not declare a provider-cached connector verified unless exercised with an authorized test account.

Both guards fail closed and name the offending path. `verify-upstream-map` reports an unmapped added, modified or deleted path, a mapped path that no longer differs from upstream, a path owned by two entries, an upstream anchor that does not exist in the pinned tree, and a missing pinned commit — in that last case it prints the exact `git fetch --no-tags <repository> <commit>` command and never downloads anything itself. `node scripts/verify-upstream-map.mjs --emit-draft` prints paste-ready entry groups for the unmapped paths; fill in `decision`, `portRule` and `checks` before pasting them into the map. `verify-rebrand` reports predecessor brand spellings and unaccounted-for old acronyms, plus identity declarations that diverge from ChatBBC. Exceptions belong in the map only for retained historical evidence or internal protocol/storage names, never as a blanket file exclusion.
