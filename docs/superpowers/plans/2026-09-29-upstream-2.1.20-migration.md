# Upstream 2.1.20 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use /subagent-driven-development (recommended) or /executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port every upstream change from Chat On Steroids `dee4b5e94b8598d7630e6db62bada9ac6050f457` (2.1.18) through `4e51a04d8e89a559e16d17fc7df6f547e57d666d` (2.1.20) into ChatBBC without weakening ChatBBC's current identity, ownership, Linux-release, Omarchy, or verification contracts.

**Architecture:** Treat upstream commits as behavioral inputs, not merge authority. Maintain a machine-validated upstream port ledger, then port each substantive change through the current ChatBBC owner with TDD and owner/epoch race tests. Keep the old upstream baseline during partial work; advance it to `4e51a04…` only after the entire 29-commit range is accounted for and the final change map is exact against the new baseline.

**Tech Stack:** Electron 44.3, TypeScript, electron-vite, Vitest, Chromium extension MV3, Node.js HTTP, JSON/Zod config validation, local Linux x64 AppImage packaging.

**Spec:** `docs/superpowers/specs/2026-09-29-upstream-2.1.20-migration-design.md`

## Scope Check

The approved spec spans several functional subsystems, but they are intentionally kept in one implementation plan because they share one migration ledger, one old/new upstream range, one downstream change map, and one final baseline-advance gate. Each functional area is still an independently reviewable task with its own tests and commit; only the ledger/map owner and final baseline transition are serialized across the whole migration.

## Global Constraints

- Old upstream baseline is exactly `dee4b5e94b8598d7630e6db62bada9ac6050f457` / upstream 2.1.18.
- Target upstream baseline is exactly `4e51a04d8e89a559e16d17fc7df6f547e57d666d` / upstream 2.1.20.
- Upstream behavior is input; ChatBBC identity and ownership remain authoritative.
- One meaningful durable fact has one authoritative owner. Do not add parallel ledgers, fallback owners, or watcher-owned truth.
- Unknown identity fails closed anywhere a wrong choice could mutate, attribute, send, bind, retire, or wake another owner.
- Preserve durable local-session identity, exact request->conversation->session-epoch attribution, browser document/navigation identity, outbox custody, worker prime-family/run identity, continuation lineage, renderer draft/load generations, secret-store ownership, and Goal ledger ownership.
- ChatBBC stays ChatBBC: slug `chatbbc`, app id `com.chatbbc.app`, connector names `ChatBBC Core` / `ChatBBC Desktop` / `ChatBBC Plugins`, bridge protocol 18 unless a separate reviewed protocol change is required.
- Preserve internal protocol/storage identifiers that the current upstream map explicitly retains (`COS_CONTEXT`, `CLF-HANDOFF`, `CLF-RESUME`, `clf`, `cos-*`, `CLF_*`, `COS_*`, `.cos-github.json`, persisted `chat-on-steroids.*` keys).
- Supported release target remains Linux x64 AppImage. Do not restore hosted GitHub Actions or Windows/macOS/ARM release promises.
- Live Omarchy palette remains main-process-owned and never persisted into manual appearance config.
- No release, tag, push, publication, or installed-app replacement is part of this source migration.
- Browser-facing acceptance requires a real signed-in ChatGPT page; renderer fixtures alone are not sufficient evidence.
- Before every implementation task: run `git status --short` and `git diff -- <task files>`; never overwrite unrelated work.
- Every task uses TDD: failing regression first, then the smallest owner-correct implementation, then targeted tests, then an independently reviewable commit.

## Review Focus

1. **Identity reuse:** a late result from an old session/document/draft/worker run must not publish into a newer owner that happens to reuse the same visible label.
2. **Presentation becoming authority:** captured HTML, composer controls, context labels, and control-API projections must never create send/session/request ownership.
3. **Partial migration bookkeeping:** every adopted upstream SHA must be recorded while the old baseline remains pinned, and the final baseline must not advance with an unaccounted SHA or stale path mapping.
4. **Secret/status leakage:** new control/status surfaces must not expose MCP path tokens, tunnel identifiers, browser/bridge credentials, plugin source config, API keys, or other owner-private fields.
5. **Linux downstream regression:** upstream release/CI/UI changes must not silently restore hosted workflows, platform promises, predecessor branding, or a second theme/release owner.

```js
export const PORT_CLASSIFICATIONS = Object.freeze([
  'port',
  'adapt',
  'already-equivalent',
  'translate',
  'provenance-only',
  'intentionally-not-imported'
]);

export const CATEGORIES = Object.freeze([
  'identity', 'assets', 'prompts', 'omarchy', 'linux-release', 'local-automation',
  'documentation', 'verification', 'composer', 'content-reference', 'control-api'
]);

function validatePortsShape(ports, errors) {
  if (ports === undefined) return;
  if (!isRecord(ports)) { errors.push('ports must be an object'); return; }
  checkKeys(ports, new Set(['from', 'to', 'entries']), 'ports', errors);
  if (!COMMIT_PATTERN.test(String(ports.from))) errors.push('ports.from must be a full 40-character lowercase SHA');
  if (!COMMIT_PATTERN.test(String(ports.to))) errors.push('ports.to must be a full 40-character lowercase SHA');
  if (!Array.isArray(ports.entries)) { errors.push('ports.entries must be an array'); return; }
  const seen = new Set();
  for (const [index, port] of ports.entries.entries()) {
    const label = `ports.entries[${index}]`;
    if (!isRecord(port)) { errors.push(`${label} must be an object`); continue; }
    checkKeys(port, new Set(['commit', 'author', 'subject', 'pullRequest', 'classification', 'paths', 'decision', 'checks']), label, errors);
    if (!COMMIT_PATTERN.test(String(port.commit))) errors.push(`${label}.commit must be a full 40-character lowercase SHA`);
    if (seen.has(port.commit)) errors.push(`${label}.commit duplicates ${port.commit}`); else seen.add(port.commit);
    nonEmptyString(port.author, `${label}.author`, errors);
    nonEmptyString(port.subject, `${label}.subject`, errors);
    if (port.pullRequest !== undefined && (!Number.isInteger(port.pullRequest) || port.pullRequest <= 0)) errors.push(`${label}.pullRequest must be a positive integer`);
    if (!PORT_CLASSIFICATIONS.includes(port.classification)) errors.push(`${label}.classification is not recognized`);
    if (!Array.isArray(port.paths)) errors.push(`${label}.paths must be an array`);
    else for (const [pathIndex, candidate] of port.paths.entries()) if (!validRepoPath(candidate)) errors.push(`${label}.paths[${pathIndex}] is not a normalized repository-relative path`);
    nonEmptyString(port.decision, `${label}.decision`, errors);
    stringArray(port.checks, `${label}.checks`, errors);
  }
}
```

- [ ] **Step 4: Add Git-range validation that is partial-safe and final-strict**

Add a helper that uses the locally fetched upstream objects:

```js
export function validatePortHistory(repo, map) {
  if (!map.ports) return [];
  const errors = [];
  const { from, to, entries } = map.ports;
  for (const commit of [from, to]) {
    try { runGit(repo, ['cat-file', '-e', `${commit}^{commit}`]); }
    catch { errors.push(`port range commit ${commit} is missing; fetch it explicitly from ${map.upstream.repository}`); }
  }
  if (errors.length) return errors;
  const expected = runGit(repo, ['rev-list', '--reverse', `${from}..${to}`]).trim().split('\n').filter(Boolean);
  const allowed = new Set(expected);
  for (const port of entries) if (!allowed.has(port.commit)) errors.push(`port commit ${port.commit} is outside ${from}..${to}`);
  if (map.upstream.commit !== from && map.upstream.commit !== to) errors.push('upstream.commit must equal ports.from during migration or ports.to after completion');
  if (map.upstream.commit === to) {
    const actual = new Set(entries.map(port => port.commit));
    for (const commit of expected) if (!actual.has(commit)) errors.push(`final port ledger is missing ${commit}`);
    for (const commit of actual) if (!allowed.has(commit)) errors.push(`final port ledger contains out-of-range ${commit}`);
  }
  return errors;
}
```

```ts
const ANY_DIRECTIVE_TEXT = /(^|\n)[ \t]*:{2,3}[a-z][\w-]*(?:\{[^}\n]*\})?[ \t]*(?=\n|$)/i;

export function hasProviderDirective(text: string): boolean {
  LEAF_DIRECTIVE.lastIndex = 0;
  CONTAINER_OPEN.lastIndex = 0;
  return LEAF_DIRECTIVE.test(text) || CONTAINER_OPEN.test(text);
```
