# Native final during an assistant-section remount — 2026-09-19

An exact ChatGPT Fiber final could arrive while React had removed its assistant section. The content script captured the correct generation before the asynchronous scan, but rechecked ownership through the now-missing live node and then re-read `generationTurn()` before emitting `turn_end`. A proven final could consequently lose its local owner or fail to close its turn. The open turn blocked downstream completed-turn handling, including eligible workflow checkpoints and normal Goal/Loop decisions.

`extension/content.js` now retains that snapshot's owner only if the same generation and user question remain current, the captured sections are unmounted, no replacement assistant is mounted, and the exact scan stamp identifies the captured section. It closes the turn from that captured section when the current DOM section is absent. An already-settled section's node/signature tombstone still owns late revisions from its original turn after a follow-up starts. A new question or replacement assistant cannot claim the detached live section's final.

`test/content-script.test.ts` covers an unmounted exact final, a newer question, a replacement assistant, and the existing in-flight scan of an older turn during a follow-up. The final four-suite run passed 909 tests; TypeScript typecheck and Electron/Vite build passed. The complete `npm run verify` run before the final ownership correction reported two failures: the older-turn test (subsequently passing focused and in the final four-suite run) and an unrelated, independently reproducible `test/tunnel.test.ts` executable-hint expectation against the existing bundled fallback. The tunnel subsystem was not edited.

Live read-only inspection confirmed the assistant-section/Fiber-stamp shape on an accessible signed-in ChatGPT tab. The active executor tab refused attachment, and the changed extension was not reloaded into active user conversations; installed live reproduction and end-to-end behavior remain unverified. A genuinely completed native turn with unfinished semantic work still requires the user's existing enabled Goal/Loop or queued workflow-checkpoint policy; this change does not create a new continuation policy.
