## 2.2.1 Upstream 2.1.20 migration

This release brings ChatBBC forward to the upstream 2.1.20 feature/fix range while preserving
ChatBBC's own identity, Linux-only release policy, storage compatibility, and fail-closed
ownership rules.

### Added

- **Optional local control API.** Advanced Setup can enable a loopback-only, read-only status API
  for trusted local tooling. It is off by default, uses a per-launch bearer token, exposes an
  explicit allowlist of status fields, and never gives the renderer the token, endpoint, paths,
  credentials, or execution authority.
- **A more capable composer.** Goal/Loop mode editing, Plan generation, model/effort projection,
  context estimates, queue presentation, and composer motion now follow the current upstream UI
  while keeping durable delivery and draft/session ownership in the existing ChatBBC owners.
- **Provider content references render cleanly.** ChatGPT content directives are resolved through
  one shared presentation layer. Unknown provider directives fail to a translated fallback instead
  of leaking raw syntax, while captured provider HTML remains presentation evidence only.

### Fixed

- **Worker completion reports no longer call never-offered queued messages unread.** Reusable
  workers keep genuinely queued work queued, while offered or uncertain messages retain the
  appropriate caveat.
- **Bridge discovery is friendlier without weakening pairing.** `/hello` can report compatibility
  as unknown when the extension protocol header is absent, while privileged pairing still rejects
  a missing or incompatible protocol.
- **Project shell titles no longer become conversation titles.** Generic `ChatGPT - <project>`
  page titles are ignored until a genuine conversation title is observed.
- **API keys survive invisible copy/paste characters.** API-key slots strip control/invisible
  characters on read and write; unrelated stored secrets keep their previous behavior.
- **Updater packaging detection is deterministic in tests and explicit callers.** Passing an
  explicit missing AppImage path no longer inherits the host process's ambient `APPIMAGE` value.
- **Provider-content fallback text is translated** across every shipped renderer locale.

### Compatibility

- ChatBBC remains **Linux x64 AppImage-only**.
- Bridge protocol remains **18**; no protocol migration is required.
- Upstream provenance is now pinned to upstream version **2.1.20**
  (`4e51a04d8e89a559e16d17fc7df6f547e57d666d`).
- The bundled companion is versioned with the app at **2.2.1**. Reload the matching
  `ChatBBC-Extension.zip` after updating so the app and companion stay on the same release.
