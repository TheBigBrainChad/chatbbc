## 2.2.0 ChatBBC: local Linux release

This release renames the desktop to **ChatBBC**. Same workspace, same tools, same conversations — a new
name, a new mark, and a release process that runs on this machine instead of on a hosted
runner.

### Changed

- **One product name everywhere.** The app, the companion extension, the window title, the tray
  tooltip, the setup and plugin screens, and the packaged executable are all ChatBBC. The
  ChatGPT connectors are now **ChatBBC Core**, **ChatBBC Desktop** and **ChatBBC Plugins**;
  existing conversations keep working, but a connector added before this release has to be
  replaced with the matching one because its title changed.
- **A new mark.** One rounded speech bubble carrying a geometric BBC lettermark, drawn as
  vector paths so it stays legible at tray size and in both light and dark themes.
- **The desktop follows your Omarchy theme.** Point ChatBBC at the live Omarchy palette and it
  repaints with the theme you are actually running — background, ink, accent, sidebar,
  selections and the terminal — without a restart and without touching your settings. The
  reader watches the materialized `~/.local/state/omarchy/current/theme/colors.toml`, ignores
  everything a palette file cannot supply, and falls back to your saved manual palette when no
  valid palette is present. Turn **Follow Omarchy theme** off and your own colours return
  immediately; the toggle survives a Reset Appearance, which still resets only the manual
  palette and typography.
- **Linux x64 is the only shipped target.** `dist:linux:x64` produces
  `ChatBBC-Linux-x64.AppImage`, and the release pipeline refuses every other host or target
  instead of assembling an artifact it cannot test here. The unpacked directory stays available
  for local checks. Windows and macOS source stays in the tree as unmaintained compatibility
  material; it is not a supported download.
- **Image processing uses Sharp's official WebAssembly backend on Linux.** The native
  Sharp/libvips binary collides with Electron's Linux GLib at runtime; the package carries
  only the WebAssembly payload and exercises a real PNG conversion before release.

### Fixed

- **A stale companion is now a visible mismatch.** The app and the extension both declare
  bridge protocol 18, so an older companion paired with this app reports the protocol it speaks
  instead of failing silently.

### Release process

- Verification, packaging and publication are local commands (`npm run verify`,
  `npm run verify:ui`, `npm run dist:linux:x64`, `npm run release:local`). There are no hosted
  workflows in this repository and no server-side release steps.
- `npm run release:local` stages a candidate only from a clean tree whose five version
  declarations agree: the AppImage, `ChatBBC-Extension.zip`, `ChatBBC-Native-Sources.tar.gz`,
  a `BUILD-MANIFEST.json` naming the exact commit and the gates that actually ran, and a
  `SHA256SUMS.txt` that is verified after it is written.
- `npm run release:publish -- --tag v2.2.0` is a separate, explicit step. It rebuilds the
  candidate, requires the named local tag to be exactly at HEAD, refuses an existing release,
  uploads a draft, re-downloads the attached bytes and compares them with the tested ones
  before the draft is made public.
- The packaged build's automated GUI smoke covers the window, shell, composer and appearance
  against an isolated profile. A human session on the real desktop and the provider-side
  connectors still have to be exercised by hand; the manifest records that as pending rather
  than claiming it.

### Upgrading

Install the AppImage, then load `ChatBBC-Extension.zip` in your browser and reconnect. Nothing
in this release rewrites your saved settings or sessions.
